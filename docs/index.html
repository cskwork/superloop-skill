/loop이 심장박동이라면 superloop은 박동마다의 규율입니다. 틱당 검증된 작업 1개, 디스크 원장에 기록, 컨텍스트 압축에도 살아남는 자율 루프. /loop is the heartbeat; superloop is the discipline behind each beat. One verified unit of work per tick, written to a durable ledger that survives context compaction.

superloop qa tick #7 commit group a3f9c12 (A20-812)
  ORIENT   ledger read, cursor at 8c1d04f
  PICK     1 unit: blast radius of a3f9c12
  EXECUTE  intent / blast-radius / evidence pass
  VERIFY   42 tests green, API body asserted
  RECORD   ledger appended, cursor advanced
  PACE     cron refires in 30m
queue: 2 open, 5 done, 0 blocked

모든 틱은 같은 해부 구조를 따른다Every tick follows the same anatomy

미션이 무엇이든 한 틱은 여섯 단계로 끝납니다. 단계 하나라도 건너뛴 틱은 기록되지 않은 틱이고, 기록되지 않은 일은 일어나지 않은 일입니다. Whatever the mission, a tick is six steps. A tick that skips a step is a tick that was never recorded, and unrecorded work never happened.

01ORIENT
원장을 읽는다Read the ledger

디스크의 원장이 유일한 진실. 현실(git)과 어긋나면 현실이 이긴다.The on-disk ledger is the only memory. When it disagrees with git, reality wins.

02PICK
단위 1개만 고른다Pick one unit

가장 작은 검증 가능한 단위 하나. 배치 금지, 일거리 발명 금지.The smallest verifiable unit. No batching, no inventing work to look busy.

03EXECUTE
supergoal 규율로 실행Execute with supergoal

최소 수정, 실패 테스트 먼저. 기존 스킬을 재사용하고 재발명하지 않는다.Smallest correct change, failing test first. Reuse existing skills, never reinvent.

04VERIFY
실측으로 증명Prove against ground truth

실제 테스트, 빌드, HTTP 응답, 읽기 전용 DB 증거. 증거 없는 done은 없다.Real tests, builds, HTTP bodies, read-only DB evidence. No done without proof.

05RECORD
원장에 기록Write it down

틱 로그는 append-only. 커서를 전진시키고 증거 경로를 남긴다.The tick log is append-only. Advance the cursor, point to the evidence.

06PACE
다음 틱을 설계Pace the next tick

캐시 인지 페이싱, 이벤트 대기는 폴링 대신 Monitor. 멈출 때는 깨끗하게.Cache-aware delays; Monitor instead of polling for events. Stop cleanly.

Missions

네 가지 내장 미션Four built-in missions

반복할 가치가 있는 일에 루프를 붙입니다. 각 미션은 큐의 출처, 단위의 정의, 검증 기준을 스스로 가지고 있습니다. Attach a loop to work worth repeating. Each mission defines its own queue source, unit of work, and verification bar.

/loop 1d /superloop docs

자동 문서화Auto documentation

최근 커밋과 어긋난 문서, 빠진 체인지로그를 틱마다 1건씩 코드 근거와 함께 최신화합니다.Each tick grounds one stale doc or missing changelog entry in the current code, with cited anchors.

/loop 1h /superloop smells

버그·코드스멜 사냥Bug and smell hunting

최근 변경된 코드에서 스멜 1건을 골라 red-green으로 외과적으로 고칩니다. 전체 테스트 그린이 종료 조건.Pick one smell in recently-touched code, fix it red-green and surgical. A green suite is the exit bar.

/loop 30m /superloop qa

최근 커밋 QAQA on recent commits

마지막 검증 SHA 이후 커밋의 의도, 블라스트 레디우스, 사이드이펙트를 증거와 함께 판정합니다.Judge each commit group since the last verified SHA: intent, blast radius, side effects, with evidence.

/loop /superloop jira

Jira 티켓 해소Jira ticket resolution

틱당 티켓 1건을 12단계 파이프라인으로. 배포 게이트는 자율 모드로도 건너뛸 수 없습니다.One ticket per tick through a 12-stage pipeline. The deploy gate cannot be skipped, even on autonomy.

jira 미션 파이프라인The jira mission pipeline

로컬 증명이 끝나기 전에는 어떤 것도 밖으로 나가지 않습니다. aidt-dev 머지는 Jenkins 배포를 의미하므로 명시적 승인이 필요합니다.Nothing leaves the machine before local proof is complete. Merging to aidt-dev triggers a Jenkins deploy, so it waits for explicit approval.

무인 운전을 위한 안전 장치Safety rails for unattended runs

루프는 사용자가 자리를 비운 동안 돕니다. 그래서 자율성보다 게이트가 항상 우선합니다. The loop runs while you are away, which is exactly why the gates always outrank autonomy.

동의 게이트Consent gates

공유 브랜치 push·merge, 배포, Jira 전이, 데이터 쓰기는 awaiting-approval로 멈추고 명시적 APPROVED를 기다립니다. 티켓만 멈추고 루프는 계속 돕니다.Pushes, merges, deploys, Jira transitions and data writes pause as awaiting-approval until an explicit APPROVED. The ticket pauses; the loop keeps working.

서킷 브레이커Circuit breaker

같은 단위 3연속 실패는 blocked, 미션 전체 3연속 실패는 루프 중단 후 보고. 반복이 컨텍스트를 망치기 전에 멈춥니다.Three consecutive failures on a unit means blocked; three across the mission stops the loop and reports, before iteration poisons the context.

빈 큐 백오프Empty-queue backoff

할 일이 없으면 대기 시간을 늘리고, 3연속 빈 틱이면 루프 종료를 제안합니다. 바빠 보이려고 일을 만들지 않습니다.No work means longer delays; three empty ticks in a row proposes stopping. It never invents work to look busy.

원장 우선Ledger before memory

멱등 키 기반 큐와 append-only 틱 로그가 디스크에 남아, 크래시나 컨텍스트 압축 후에도 정확히 이어서 재개합니다.An idempotent queue and append-only tick log live on disk, so a crash or compaction resumes exactly where it stopped.
