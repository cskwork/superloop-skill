# changelog 2026-06-18

## reference/loop-runner-pitfalls.md 추가 - 직접 디스패처를 만들 때의 셸 함정

**무엇**: 내장 `/loop` 대신 **자체 디스패처**(작업 큐를 돌며 유닛마다 `claude -p`/에이전트를
spawn하는 셸 스크립트)를 만들 때 일을 조용히 누락시키는 셸 버그 3종과, 비용 0으로 실패 경로를
검증하는 법을 담은 reference. SKILL.md Reference map에 연결.

**왜 이 3종인가** (실제 디스패처에서 재현·수정하며 추출, 모두 일반화)

- **자식 프로세스가 디스패치 루프의 stdin을 소비**: `while read u; do run_agent "$u"; done < <(produce)`
  에서 `run_agent`(claude -p/ssh/ffmpeg 등)가 stdin을 읽으면 공유 파이프의 나머지 줄을 먹어,
  **첫 유닛만 처리되고 나머지는 무오류·exit 0으로 사라진다**. 해결=자식 stdin을 `</dev/null`
  (헤드리스 에이전트는 애초에 stdin을 읽으면 안 됨) 또는 루프 입력을 전용 fd로 격리.
- **한 유닛의 게이트/에러가 전체 큐를 중단**: 게이트(사람 승인)·실패에서 루프를 `return`/`exit`하면
  남은 유닛이 전부 드롭. 해결=루프는 계속, 실패는 집계해 종료코드로만 노출. 게이트는 그 유닛만 멈춘다.
- **`set -e`가 `func || rc=$?` 안에서 비활성 → 무한 재시도**: bash는 조건의 일부로 호출된 함수
  내부에서 `set -e`를 끈다. 실패 단계가 미마킹이면 다음 단계 계산이 같은 단계를 다시 골라 무backoff
  무한 재시도(유료 에이전트가 영원히 돈다). 해결=단계 실패를 `|| return 1`로 명시 + 일시 오류
  (5xx/429)만 상한·backoff 재시도, 타임아웃 등은 즉시 실패.

세 버그 모두 **해피패스·dry-run에서는 멀쩡**하고, 실제 자식 실행/게이트/일시 장애에서만 드러난다.
그래서 reference는 "실패 경로를 먼저 테스트하라"를 강조한다.

**왜 superloop에 담나**: 특정 프로젝트의 루프 구현 코드는 담지 않는다(이 repo는 public).
대신 어떤 루프 러너를 만들든 재사용되는 **일반화된 함정·검증 지침**만 담아, superloop의 "틱당 1단위
/ 게이트는 멈춰도 루프는 계속" 규율을 러너 레이어에서 보강한다.

**검증**: 각 함정의 무료·결정적 검증법을 reference에 포함 — stdin drain 셸 1줄 재현, 게이트
dry-run, 가짜 바이너리로 상한 재시도 실증(에이전트 비용 0).
